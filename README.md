# FindYourJob

Русскоязычный сервис поиска работы: главная страница с фильтрами и карточками вакансий, регистрация, вход и выход. Поиск открыт гостям, зарегистрированный пользователь получает личную сессию.

## Быстрый запуск

Требуется Node.js 22+ (проверено на Node.js 24).

```bash
npm ci
cp .env.example .env
npm start
```

Сайт доступен на порту `3000`. Для разработки: `npm run dev`.
Без `DATABASE_URL` используется [PGlite](https://pglite.dev/) — встроенный PostgreSQL; пользователи и сессии сохраняются в `.data/postgres`. Отдельный сервер базы для локального запуска не нужен. Не запускайте несколько экземпляров приложения с одной директорией PGlite.

## PostgreSQL

Для сервера используйте PostgreSQL 16+ и отдельную базу с учётной записью приложения. Укажите в `.env`:

```dotenv
DATABASE_URL=postgresql://fyj:YOUR_PASSWORD@localhost:5432/fyj
```

Таблицы `users` и `sessions`, а также индекс срока действия сессий создаются автоматически при старте. Данные запрашиваются параметризованными SQL-запросами. При переключении с PGlite на PostgreSQL данные автоматически не переносятся.

Для публичного размещения задайте `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен` и настройте HTTPS. Только за одним доверенным reverse proxy задайте `TRUST_PROXY=1`. В production cookie передаются только через HTTPS. Пароли хешируются с помощью scrypt с индивидуальной солью. HttpOnly/SameSite-сессии действуют 7 дней; токены в базе хранятся в виде SHA-256-хеша. Вход ограничен по IP, небезопасные запросы с другого сайта отклоняются.

## Поиск hh.ru

Используется официальный публичный API `https://api.hh.ru`, а не сбор HTML. Настройте исходящий HTTPS-доступ к `api.hh.ru`. Пользовательский OAuth-токен для поиска публичных вакансий не требуется. Для размещения задайте `HH_USER_AGENT` с названием приложения и контактным адресом согласно требованиям hh.ru.

Фильтры:

- профессия в названии вакансии;
- компания через поле языка поиска hh.ru `COMPANY_NAME`;
- регион с выбором из справочника hh.ru;
- минимальная зарплата и валюта;
- зарплата на руки / до вычета налогов;
- опыт работы и удалённый формат.

Сортировка — по дате публикации, 20 вакансий на странице. Поиск компании текстовый, возможны совпадения названий у разных работодателей. Ограничение глубины выдачи hh.ru — 2000 вакансий (100 страниц).

**Особенность налогов:** API hh.ru не предоставляет отдельный поисковый параметр `gross`. Сервис фильтрует полученную страницу по `salary.gross`, не пересчитывая налоги. Число hh.ru относится к исходному поиску; страница после фильтра может быть пустой, при этом на следующих могут быть совпадения. Это явно указано в интерфейсе. Минимальная зарплата передаётся hh.ru в выбранной валюте; она не преобразуется в сумму после налогов. Вакансии без зарплаты скрываются при заданной сумме или налоговом фильтре.

Карточки содержат компанию, регион, зарплату, опыт, фрагменты описания и безопасную HTTPS-ссылку на hh.ru. Ошибки API, таймауты и ограничение частоты отображаются пользователю. Данные вакансий не сохраняются в базе; справочник регионов кешируется в памяти на сутки.

## Проверки

```bash
npm test
npm run test:browser
```

Интеграционные тесты проверяют регистрацию, дубликаты, вход, ротацию и истечение сессий, выход, CSRF, валидацию, преобразование фильтров, карточки и ошибки hh.ru. Внешний API заменён тестовыми ответами, поэтому эти тесты не подтверждают доступность живого hh.ru.

Для браузерных тестов нужен Chromium. По умолчанию используется `/usr/bin/chromium`; иной путь задайте переменной `CHROMIUM_PATH`. Проверяются регистрация, вход/выход, поиск, ошибки и отсутствие горизонтального переполнения на мобильных страницах.

Для отдельной временной PostgreSQL можно запустить интеграционные тесты с `TEST_DATABASE_URL`. Используйте **только пустую тестовую базу**, поскольку тесты создают пользователей и изменяют сроки всех сессий в ней.

## Структура

- `src/app.js` — HTTP-маршруты и авторизация.
- `src/db.js` — подключение PostgreSQL/PGlite и схема.
- `src/hh.js` — запросы и нормализация данных hh.ru.
- `public/` — адаптивные страницы и клиентский JavaScript.
- `test/` — интеграционные и браузерные проверки.

Пока не реализованы подтверждение email, восстановление пароля, избранное и уведомления. Не выдавайте этот прототип за готовую систему найма без настройки HTTPS, резервного копирования и эксплуатационного мониторинга.
